## Context

`createSyncedLinks` writes to its cache at once and sends the writes in
order from an in-memory outbox. Offline, the writes wait until
`connect(transport)`. If the page reloads first they are lost, and after a
reconnect the cache keeps what it loaded even if other clients changed it
meanwhile (the "stale data" deviation in `packages/ui-links/README.md`).

## Goal

Offline-first sync: the outbox and the cache survive a reload, and a
reconnect brings the cache up to date.

## In scope

1. Persist the cache with `persistLinks` and the outbox (as Links Notation)
   with the same adapter.
2. Keep temporary addresses across reloads (the counter and the remap).
3. On reconnect: replay the outbox, then reload the subscribed restrictions
   (or ask the server for the changes since a version, if the server keeps
   a change log; decide in the pull request) and report the differences
   with `origin: 'remote'`.
4. Conflict rule: the server's answer wins; a refused write is rolled back
   and reported, as today.

## Acceptance criteria

- A test writes offline, recreates the client from the same adapter,
  connects, and finds the writes on the server with their real addresses.
- A test changes the server while a client is offline; after the reconnect
  the client's cache equals the server's readable links.
