## Context

The synced client of `@link-foundation/ui-links` talks to its own JavaScript
server, which serves link-cli's `LinksOperation` protocol plus three
extensions (`auth`, `subscribe`, `unsubscribe`) and a permission layer.
link-cli's own client already talks to the JavaScript server
(`examples/ui-links-tcp.mjs`), but the opposite direction needs link-cli to
have the extensions: the permission layer ({{L02}}) and subscriptions
({{L03}}).

## Goal

The client and the examples of ui-links run unchanged against
`clink --serve`, so link-cli is the production server and the JavaScript
server stays a reference and a test double.

## In scope

1. A CI job that installs a released `clink`, starts `clink --serve` with
   permissions, and runs the client tests against it.
2. Align the deviations listed in `packages/ui-links/README.md` ("Compatibility
   with link-cli") with what link-cli decided in {{L02}} and {{L03}}.
3. `examples/ui-links-permissions.mjs` with a `--server clink` option.

## Acceptance criteria

- The client tests pass against both servers.
- The deviations section lists only the differences that remain by design.
