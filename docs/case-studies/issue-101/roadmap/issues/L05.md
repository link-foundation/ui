## Context

`clink --serve` speaks LinksOperation in Links Notation text and in the
binary codec of links-notation for doublets. The binary codec can already
carry links of three references (`--arity 2..3`, see
`docs/protocol/binary-links-notation.md`), but that only changes how a LiNo
document is packed: the operations and the store are still doublets. With
triplets stored in doublets ({{L04}}), the same server should serve
triplets "directly via links notation (text + binary) API similar to how we
do with doublets".

## Goal

Triplet operations in the protocol, in text and binary, in C# and Rust, with
`RemoteLinks` and `@link-foundation/link-cli-client` support.

## In scope

1. `(count: (i T f t))`, `(each: (i T f t))` → `(i: T f t)` per triplet,
   `(create: (T f t))`, `(update: (i T f t))`, `(delete: i)`; substitution
   queries with three-part links.
2. A server mode (`--triplets`) or a per-request form, decided in the issue,
   so doublet clients keep working.
3. Subscriptions ({{L03}}) and permissions ({{L02}}) on triplets, where
   those exist.
4. Triplet replies packed with `--arity 2..3` when the client asks for it,
   so a triplet travels as one link of three references.
5. The recorded conversation in `docs/protocol/` extended with triplets,
   replayed by both ports.

## Acceptance criteria

- The doublet conversation replays unchanged.
- A triplet conversation (create, each by type, update, delete) replays in
  text and in binary in C# and Rust.
