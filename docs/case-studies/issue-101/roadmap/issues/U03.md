## Context

ui-links keeps names in a sidecar, as link-cli does (`createNames()`, the
`<db>.names.links` file of `clink`). A name is not a link, so the synced
client does not receive names with the links it loads, a subscription does
not push renames, and the permission layer cannot hide a name: today
`(get-by-name: …)` checks only that the named link is readable.

## Goal

Names as links in the same storage (the name text as a sequence of
character links or as a string value link), so names sync, persist and obey
permissions like any other link.

## In scope

1. An encoding of a name as links (for example `(n: Name l)` where `l` is the
   named link and the text is a sequence of unicode-symbol links), consistent
   with how link-cli stores names in its names database, whose own links
   already are doublets.
2. `createLinksNames(links)` with the interface of `createNames()`, so the
   server, the queries and LiNo import/export accept either.
3. The synced client loads the names of the links it loads.

## Acceptance criteria

- The server tests pass with names as links.
- A rename by one client reaches another subscribed client.
- A subject cannot read the name of a link it cannot read.
