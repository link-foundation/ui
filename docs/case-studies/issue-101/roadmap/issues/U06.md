## Context

`writeDocumentLinks` and `readDocumentLinks` of `@link-foundation/ui-store`
write a UI document to any doublets storage and read it back, once
(`examples/ui-store-links.mjs`). They do not yet keep a store and a synced
links client in step: an edit in the store does not become link writes, and
a pushed link change does not become a store operation.

## Goal

`bindStoreLinks(store, links, { roots })`: every store operation becomes the
smallest set of link writes, and every change of the links (local, remote or
rollback) becomes store operations, so two browsers edit one document
through a links server.

## In scope

1. A mapping from store operations (`set`, `insert`, `remove`,
   `setPositional`, …) to link writes over the document encoding of
   `writeDocumentLinks`.
2. The reverse mapping from link changes to operations, with origin
   `links`, so undo history ignores remote changes.
3. A two-client test through `createLinksServer` and a Playwright example.

## Acceptance criteria

- Two synced clients bound to two stores converge after concurrent edits of
  different nodes.
- A write refused by the server rolls back the store too.
