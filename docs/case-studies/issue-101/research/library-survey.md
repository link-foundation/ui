# Library survey: partial, permission-filtered client caches with optimistic writes

What exists for each part of [requirements](../requirements.md) R7–R13 and
R20: storages, synced clients, permission filtering and the formats of
link-cli. The survey was done on 2026-11-02 (GitHub's licence API and the
LICENSE files, `npm view`, the official documentation, and local runs where
said). What could only be inferred or not confirmed is marked
**[unverified]** or **[inferred]**. The decisions that follow from it are in
[the solutions](../solutions.md).

## What this pull request reuses, and why

- **doublets-web** (Unlicense) is the reference interface of every storage
  (`create`, `update`, `delete`, `count`, `each`) and one of the storages
  (`openDoubletsWebLinks`). It keeps links in memory only, so persistence is
  a layer of its own (`persistLinks` with the IndexedDB, `localStorage` and
  Links Notation adapters).
- **`node:sqlite`** (Node.js, Deno, Bun) or any database with `exec` and
  `prepare` backs `createSqlLinks`; the browser SQLite of sqlite-wasm on OPFS
  is planned in [ui#111](https://github.com/link-foundation/ui/issues/111).
- **links-notation** and **`@link-foundation/link-cli-client`** (Unlicense)
  give the text and binary forms of the protocol of `clink --serve`, which
  `createLinksServer` speaks, so link-cli's own client talks to it.
- **Nothing else is a dependency.** The synced client follows the
  replay-or-rebase family below (Meteor's method stubs, Replicache, Zero,
  InstantDB): a write runs on the local copy at once and is sent in order;
  the server's answer wins and a refused write is rolled back. Reads are
  filtered (InstantDB, Hasura, Supabase), not rejected (Firestore): a link the
  subject may not read is missing from every answer and push. No library
  offers both with permissions stored as links: RxDB's persistent storages
  are premium, TinyBase and the CRDTs have no permission model, Zero and
  Electric need Postgres, and Triplit is AGPL.

## Notes

**Meteor, the reference design.** A publish function is a server-side, permission-aware query whose results feed one merged client cache per collection. On the client, `insert`/`update`/`remove` call stubs that update minimongo right away. "When the server responds, the client updates the local cache with the writes that actually occurred on the server." Inside a stub, `isSimulation` is true. Our links equivalent would be: a publication is a link query plus a permission predicate, the cache holds `(id, source, target)` rows, and a method stub is a substitution query run against the local doublets store. I did not re-check the internals of Meteor's "merge box" (the server-side copy of what each client has).

**Two ways to apply permissions to reads.** Firestore rejects a whole query if it might return a document the user cannot read. InstantDB, Hasura, Triplit and Supabase RLS remove the unauthorised rows instead. Filtering is friendlier, but the server pays for it per subscriber: Supabase notes that 100 subscribers means 100 authorisation checks per change. With writes it matters which side checks: Triplit checks permissions only on the server, so an invalid optimistic write is rolled back after the fact.

**Optimistic-write families.** There are three:

- **Replay or rebase.** Meteor stubs, Replicache, Zero, InstantDB. The server re-runs the same mutator and its result wins.
- **Assumed-state compare-and-swap.** RxDB's `assumedMasterState`, CouchDB `_rev`.
- **CRDT merge.** Yjs, Automerge, TinyBase, Triplit.

Replay or rebase suits links best: a link write is small and server rules can reject it.

**Browser SQLite.** Use the official sqlite-wasm `opfs-sahpool` when COOP/COEP headers are not set, or `opfs`/`opfs-wl` when several tabs need the same database. wa-sqlite has the widest range of VFSs, including an IndexedDB-backed one that works everywhere. `kvvfs` covers localStorage.

**Runtimes.** I ran `DatabaseSync` from `node:sqlite` successfully on Node v26.13.0, Deno 2.9.7 and Bun 1.4.4. Deno docs say `node:sqlite` arrived in Deno v2.2. Bun's Node-compat page lists `node:sqlite` as "🟢 Fully implemented", with caveats such as `backup()` running synchronously. I could not find which Bun version first shipped it **[unverified]**.

**doublets-web.** The source builds the store on `doublets::mem::Global` (heap memory) with `TLink = u32`, so nothing persists by itself. An IndexedDB, OPFS or localStorage snapshot or log has to be layered on top **[inferred from the source]**. `each` expects the callback to return `constants._continue`, and returns `_break`/`_continue`.

**link-cli.** `clink --db db.links --serve 127.0.0.1:7777` serves a database over TCP in two protocols:

- **text**: UTF-8 LiNo, each message ending with a line holding `.`
- **binary**: `--protocol binary`, with `--external-references`, `--arity` (default 2, so doublets only; `2..3` adds triplets) and `--packed-widths`

C# and Rust both provide `RemoteLinks`. There is also a JS client, `@link-foundation/link-cli-client` (npm 0.1.0, Unlicense), for Node, Bun and Deno that can also run the in-process WebAssembly store. Browsers cannot open raw TCP, so a browser client needs a WebSocket bridge **[inferred]**.

**Links Theory definitions.** From "The Links Theory 0.0.2" (Habr, 2025; the Russian original is "Глубокая Теория Связей 0.0.1"), with matching set-theoretic definitions in `link-foundation/deep-theory` (Unlicense):

- References: L ⊆ ℕ₀.
- A **link** is an n-tuple of references to links that has its own reference.
- **Doublets network:** λ: L → L × L, for example 3 → (1, 2). The repo writes this as "anetd : L → L²", with D = L².
- **Triplets network:** λ: L → L × L × L, for example 4 → (1, 2, 3). The extra slot can be read as "beginning, type, end", which can express subject-verb-object.
- **n-tuple / vector network:** λ: L → Lⁿ, and lengths can vary.

The article says triplets can do everything doublets can, and that both can encode sequences of any length; it states the latter without a formal proof. It does not discuss RDF. The comparison to RDF (subject, predicate, object) and Datascript datoms (entity, attribute, value, tx) is mine: those triples have no identity of their own, whereas a links-theory triplet does.

- The GitHub API shows NOASSERTION for Meteor, Yjs, Firebase and sqlite-wasm; I read the actual LICENSE files instead.
